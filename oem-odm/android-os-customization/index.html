Android OS Customization for Rugged Terminals

A device configured before it ships costs less than one configured after it arrives. Android customization decides the system version your application runs against, whether Google Mobile Services are present, what the operator sees when the device starts, and which applications are already installed when it is unpacked.

The operating system version is tied to the build validated for that hardware, not chosen freely. If your application requires a specific version, tell us at the start so it can be matched to the right platform rather than discovered during integration.

BUILD TYPE

GMS build or plain AOSP

Build with GMS

Where your deployment depends on Google Mobile Services — managed provisioning, Play services or applications from the store — the platform needs a build carrying GMS certification.

  • Needed when MDM enrolment relies on Google services
  • Needed when third-party applications expect Play services
  • Stated as a requirement so the correct build is used

Plain AOSP build

Single-purpose devices often run better without consumer services, both for behaviour and for the support burden.

  • No consumer accounts or store access on the device
  • Smaller surface for unauthorized changes in the field
  • Stated as a requirement so it is validated before production

SEQUENCE

How the image is frozen

Before the sample

  • Version, build type and application list agreed
  • Behaviour requirements captured in the specification
  • Any SDK or integration requirement confirmed with your team

At the sample

  • Your team runs its own integration on real hardware
  • Behaviour checked against what was specified
  • Once accepted, the image is frozen for production

Changing the image after units are built costs time on every device in the batch, which is why the specification is signed off before production rather than at delivery. See the full project sequence on the Custom Solutions page.

FAQ

Android customization questions

Which Android versions are available?
It depends on the platform: the XH-500 rugged tablet runs Android 12 as standard with Android 13 as an optional configuration, and other models have their own supported versions. Confirm the version you need against the platform you intend to buy, because the choice is tied to the hardware's validated build rather than picked freely.
Can we choose a GMS build or a plain AOSP build?
Yes, subject to what the platform supports. Builds carrying GMS certification are needed when your deployment depends on Google Mobile Services; deployments that run a single controlled application often prefer a plain AOSP build with no consumer services installed. State which one the application requires.
Can the device be locked to a single application?
Kiosk behaviour, launcher replacement and operator restrictions belong to the software scope of the project. Tell us what the operator should and should not be able to reach, and the behaviour is validated on the engineering sample before mass production.
Who handles updates after delivery?
Decide this before production. Some deployments want images frozen for years so nothing changes on a working device; others want a defined update route. Either way, agree it during feasibility, because the answer affects how the image is built and documented.
