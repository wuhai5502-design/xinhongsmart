Software Customization & SDK Integration

The device is only useful once your software can drive its hardware. Software customization covers the Android image itself — version, build type, launcher, pre-installed applications — and the integration layer: the APIs and SDKs that let your application read the scan engine, capture a fingerprint, read an identity card or poll the RFID reader.

INTEGRATION

Modules your application can drive

ModuleWhat your application gets
2D scan engineDecode results from Newland, Honeywell N3680 or Zebra 4710 engines, including continuous scan behaviour and the symbologies your workflow uses
Fingerprint captureImage and template records from FAP10 capacitive or FAP20 and FAP30 optical sensors; the capture profile decides the image dimensions and the record format
Identity cardsStructured data from the second-generation Chinese ID card reader, offline, and from the online version where the workflow depends on a central service
NFC and RFIDTag reads over NFC ST21NFC at 13.56 MHz (ISO/IEC 14443 Type A/B, ISO/IEC 15693) and over LF 125K / 134.2K, HF 13.56 MHz or UHF RFID depending on the platform

Formats are confirmed against your application before the order is placed, rather than discovered during integration. That is the difference between a two-week integration and a two-month one.

APPLICATION LAYER

What we put on the image

Pre-installed applications

Your APK is installed as part of the build, so devices arrive configured rather than needing a roll-out on site.

  • Your application(s) and any dependencies
  • Default language and locale for the deployment
  • Supporting tools your team expects on the device

Device behaviour

Behaviour requirements belong to the software scope, not to a manual handed to the installer.

  • Launcher behaviour and kiosk lock-down where operators should see one application
  • Boot logo and start-up animation carrying your brand
  • Policies your IT team requires before deployment

Send the APK and integration requirements at the feasibility stage so they can be validated on the sample. Changing the image after units are built costs time on every device in the batch.

FAQ

Software customization questions

What SDK support is included?
API or SDK support is provided for the modules installed in your build — the scan engine, fingerprint sensor, NFC or RFID reader and ID card reader — so your application can drive them directly. The documentation set that ships with the order is agreed when the quotation is confirmed.
Which output formats are supported?
Output formats differ per module: the fingerprint sensor produces image and template records according to the capture profile, the scan engine returns decoded symbologies, and the card readers return defined data structures. Formats are confirmed against your application before the order is placed, rather than discovered during integration.
Can our own application be pre-installed?
Yes. Applications, default language, launcher behaviour and kiosk behaviour of the Android image are part of the software scope. Send the APK and any integration requirements at the feasibility stage so they can be validated on the sample before mass production.
What happens if our software depends on privileged access?
Say so at the start. Whether elevated permissions can be provided depends on the platform and what the application needs them for, and the alternative is usually an API provided by the module vendor. It is cheaper to settle this during feasibility than after the first sample arrives.

Send the software scope
